# 键盘映射

**简体中文** | [English](../en-US/Keyboard-Mappings)

打开“设置 > 键盘映射”，可以把物理按键组合转换成新的按键输入。列表第二列显示每条规则的可选用途说明。映射只在
Simpilot 运行时生效，不修改 Windows 系统策略。

## 支持的规则

- 源：单键、一个到四个修饰键加动作键，或最多三个修饰键加两个同时按住的动作键；
- 目标：单键，或最多四个修饰键加一个动作键；
- 左右 Ctrl、Alt、Shift、Win 会分别记录；
- 左右修饰键也可单独作为源主键或目标主键，作为主键时对应一侧的修饰键槽必须均为“无”；源主键为修饰键时也不能选择 chord；
- 适用范围选择“所有应用”表示全局，或选择“指定应用”关联最多 32 个 `.exe` 进程基名，任一关联程序处于前台时生效；
- 关闭“精确匹配应用”时，使用不区分大小写的进程名前缀匹配；
- 最多保存 128 条规则。

## 添加映射

1. 选择“添加”。
2. 使用“录制源按键”，按下要转换的按键或组合后全部释放；也可以在四个修饰键槽、主键和可选的“同时按下键”下拉框中直接选择。
3. 使用“录制目标按键”，按下目标单键或快捷键后全部释放；也可以选择最多四个修饰键和一个主键。
4. 选择“所有应用”或“指定应用”。指定应用支持逐个输入名称后“添加”、浏览 EXE 文件，或“追加前台应用”（简驭最近观察到的外部前台进程）；重复名称会自动合并，所选条目可以移除。
5. 保存规则，再在设置窗口选择“应用”或“保存”。

例如，“左 Win → 右 Ctrl”关联 `Code.exe` 和 `notepad.exe` 后，仅在这两个程序之一处于前台时生效。切换到其他程序时不会启用此映射；已按住的目标键仍会在源键松开时正常释放。
指定应用列表为空时不能保存，删除最后一项不会自动变成全局。匹配始终使用程序文件名，浏览 EXE 时也只保存文件名，不区分同名程序的不同路径、窗口或网页。本功能不包含“办公／游戏”等整套场景配置切换。

源主键和目标主键下拉框都包括左/右 Ctrl、Alt、Shift、Win；chord 动作仍不允许修饰键。
动作键下拉框包括字母、数字、`F1` 至 `F24`、编辑和导航键、数字键盘、常见标点、浏览器以及媒体键。
修饰键必须明确选择左侧或右侧；录制不在列表中的特殊硬件键时，对话框会保留其完整物理键身份。

`Num Lock`（数字锁定）可录制或从主键下拉框选择，既可作为源按键，也可作为目标按键。
例如，将 `F12` 映射到 `Num Lock` 后，每次按下并释放 `F12` 都会切换数字锁定状态。
此前录制为 `VK 0x90` 的目标按键配置也可直接使用，无需重新录制。

例如，建立“左 Win → 右 Ctrl”时，源和目标的修饰键槽均保持“无”，主键分别选择“左 Win”和“右 Ctrl”，也可以分别按下并释放这两个键进行录制。
保存并应用后，按下左 Win 会立即按住右 Ctrl，松开左 Win 时释放右 Ctrl；按住左 Win 再按 `C` 可形成 `Ctrl+C`。不需要等待 250 ms，其他键先按下也可使用该修饰键目标。
普通键也可映射到左右修饰键，例如 `Caps Lock → 左 Ctrl`。真实目标键与映射目标同时按住，或多个源映射到同一修饰键时，最后一个持有者释放后才会结束目标按住状态。

例如，普通键盘可以建立“右 Ctrl”到“左 Win + 左 Shift + F23”的规则来发送 Copilot
键序列。右 Ctrl 单独使用时触发映射；在 250 ms 内继续按下 `C`、`V` 等键时，简驭会
回放右 Ctrl，使普通 `Ctrl+C`、`Ctrl+V` 继续工作。`F23` 对应 Windows 的
`VK_F23`（`0x86`），界面直接显示为 `F23`，不再显示十进制 `VK134`。
[微软虚拟键码表](https://learn.microsoft.com/windows/win32/inputdev/virtual-key-codes)列出
`VK_F23`；[微软问答中的 Copilot 键说明](https://learn.microsoft.com/answers/questions/5637848/remap-a-shortcut-for-copilot-key-on-asus-zenbook-w)
记录了该组合序列。

映射源的两个动作键必须同时处于按下状态才会形成 chord，先按哪一个都可以。映射录制
模式中的裸 `Esc` 是普通可录制按键；要放弃编辑，请使用对话框的“取消”按钮。

## 校验与限制

保存会拒绝重复源、歧义前缀、循环映射、`Win+L`、Windows 安全组合和非法按键。
多应用规则按实际共同应用检查冲突；冲突提示保留编辑内容。应用规则优先于全局规则，精确匹配优先于前缀匹配，较长的匹配前缀优先；名单顺序和数量不影响优先级。
修饰键映射到另一个修饰键时，也会拒绝包含同一源修饰键的源快捷键，避免立即映射与组合前缀等待相互冲突。
目标不支持 chord。旧配置没有 `[KeyboardMappings]` 时，其他设置和既有热键行为不变。

旧版单应用和全局配置可直接读取。v1.0.10 保存多应用规则时使用独立列表和旧版读取保护，v1.0.9 及更早版本会跳过这些规则，不会误识别成全局。降级前请备份 `Config/`；旧版保存设置可能丢失多应用规则。

Windows UIPI、管理员权限差异或安全桌面可能阻止输入注入。普通权限运行的 Simpilot
不能保证向更高权限窗口发送映射结果；失败诊断会写入 `Log/Simpilot.log`。

### 排除指定应用

“适用应用”提供“所有应用”“仅指定应用”“排除指定应用”。排除名单最多包含 32 个 EXE 文件名，任一名称匹配时当前规则不生效；名单为空时不能保存。排除仅影响当前规则，其他符合范围的规则仍可生效。无法识别前台程序时，排除规则不执行。

相同触发条件优先使用仅指定应用的规则，其次是排除范围，最后是全局规则。包含名单继续采用精确匹配优先、较长匹配前缀优先；重叠排除规则的同一源键不能设置不同目标。精确匹配关闭时，整份名单采用 EXE 文件名的前缀匹配。

v1.0.10 及更早版本会跳过排除规则，不会把它们反转成包含规则或扩大到全局。旧版保存可能丢失新规则，降级前请导出备份，恢复完整设置须使用支持该备份格式的版本。
