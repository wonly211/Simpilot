## 3. 分图结论

“通过”仅表示当前尺寸、当前内容和当前静态状态在对应视觉维度可接受。

### P01 General

**层级通过。** 页标题、两条设置、固定提交栏各司其职；保存为唯一高强调命令，应用灰化外观与当前未展示修改的状态不冲突。

**关联通过。** 设置区宽度收束，分隔线把标签和控件限制在同一行域；语言字段下的“立即保存”明确了它与普通待应用设置的差别。IR-01/02 的视觉方向得到落实，不再要求靠猜测区分提交时点。

**功能保留部分通过。** 自启动、语言和取消/应用/保存均可见。IF-03 必须修正触发时点文案；语言取消不可撤销、自启动草稿及真实提交没有在此稿中执行。

**留白通过。** 两项设置不需要撑满窗口。底部空白保持安静、原生工具感，不能因空间宽裕增加卡片、说明教程或无关功能。

### P02 Hotkeys

**层级通过。** 内置与自定义组清楚，启用列可见，局部添加/编辑/删除弱于窗口保存；列表列头、行分隔和开关构成稳定扫描路径。

**关联通过但有证据限制。** 录制图标嵌于键值控件，清除紧邻对应行，消除了部分动作寻找成本。`×` 本身仍依赖提示及辅助名称明确对象；README 声明已有名称，但截图不能验证 hover/focus 或读屏。不能据此认定缺失，也不能据此宣布原生已通过。

**可见功能保留通过。** 四项内置热键、独立清除/启用、自定义行开关、动作类型、目标和管理命令均可见。README 称完整数据有 16 条，本轮只看见前五条，不据前五条判定其余被删。录制、增删改、启用及提交仍未执行。

**目标辨识部分通过。** 相比 N15 的重复目录前缀，P02 可辨认 `AuditTool.exe` 和文件夹名称；较长文档名仍被省略但保留扩展名线索。IR-05/26 的静态扫描问题有改善，完整路径是否可取回只能待原生验证。

**留白可接受，密度仍有取舍。** 首屏仍是五行，不能将 IR-27 记为完全解决。较清楚的行高和较低首屏容量属于可讨论的取舍，不必为多塞一行牺牲可读性；后续原生布局应让新增窗口高度优先分配给列表，并验证末尾可达。当前图的滚动线索较弱属于可发现性风险，不能直接判为不能滚动。

### P03 Mapping

**层级和字段关联通过。** 源触发、目标输出两栏均将摘要与对应录制按钮放在一起；下方用途和应用范围属于整条规则，分隔线建立了层级。提交栏独立，留白没有隔断相关字段。

**可见控件保留通过，语义定稿不通过。** 对照已实际查看的 N21，保留清单如下：

| 已有内容 | P03 可见情况 |

| 源组合键摘要、录制源按键 | 均保留 |
| 源四个修饰键槽位、主键、同时按下键 | 均保留，未删可选同时按下键 |
| 目标组合键摘要、录制目标按键 | 均保留 |
| 目标四个修饰键槽位及主键 | 均保留，未增加目标 chord 字段 |
| 用途、应用、使用前台应用 | 均保留，当前长用途可读 |

完整控件不等于完整能力：下拉全部键集合、修饰键限制、源键约束、重复组合校验、Esc 录制语义和实际钩子均未验证。README 也明确完整键集合与校验不在离线稿实现。N21 原有规则说明被简化后，实施时仍须由原生控件约束及相关错误反馈保留这些规则；不要求为了证明完整性把长教程重新堆回表单。

**留白通过。** 双栏对称并未虚构目标功能，规则状态与提交栏之间有缓冲，不需要再压紧。把精确匹配移近适用应用即可，不必重做整页布局。

### P04 Menu

**一级静态层级通过。** Tools 的浅蓝选中态、右侧展开箭头及紧邻子菜单清楚表达所属关系；子菜单与父项附近对齐。Audit Tool 与分类之间保留分隔，图标槽、文字和尾部提示分工明确。

**可见语义通过。** Tools 保留 `[T]`，Review utilities 带展开箭头；Fixture folder 没有子菜单箭头，外观上可以区分启动目标与继续展开的分类。均不证明点击后实际动作。

**功能保留只确认已展示部分。** README 说明第二层文档数据仍保留，只展示一级展开。因此既不能说深层菜单已被删除，也不能仅凭数据存在判为深层菜单可达。P04 不是托盘右键菜单，不验证其命令集合。

**留白通过。** 大片灰色区域是用于展示浮层的背景，不是产品菜单的内容容器。菜单内部紧凑，轻边框和轻阴影足以建立层次，不需要增大菜单或铺满画布。

父子菜单穿越、悬停延迟、左右键、Esc、助记键、屏幕边缘翻转、深层展开及启动动作全部待原生验证。本轮不从静态相邻间距推断“不会误关闭”或“操作流畅”。
