# 键盘录制与映射架构

接管基线：Simpilot 0.18.5。键盘录制、热键处理和物理键映射均由 Simpilot
自有代码实现；设计参考公开可观察的键盘重映射行为，不包含外部键盘管理器源码。

## 1. 线程与组件

Simpilot 在单个进程内使用一个专用键盘线程。该线程拥有消息窗口、消息循环、唯一的
`WH_KEYBOARD_LL` 钩子、录制状态和映射运行时；设置窗口只通过同步控制消息提交请求。

```text
UI thread
  -> KeyboardManager control message
     -> keyboard hook thread
        -> KeyboardCaptureState
        -> KeyboardMappingEngine
        -> forced/global hotkeys
        -> Windows shortcut blocker
```

- `src/app/keyboard_capture_state.*`：无 UI 依赖的固定容量录制状态机；
- `src/app/keyboard_mapping_engine.*`：映射查找、前缀缓冲、回放和目标按键生命周期；
- `src/app/keyboard_manager.*`：线程、钩子、消息协议、录制结果投递和运行时替换；
- `src/app/keyboard_mapping_dialog.*`：映射规则编辑，不拥有钩子状态。

## 2. 录制状态机

`KeyboardCaptureState` 支持三种模式：旧全局热键、映射源和映射目标。四类低级键盘
消息均在录制期间抑制，只有出现动作键且全部已按物理键释放后才完成。重复 key-down
不会重复加入状态；结果带会话号并且只能消费一次。

- 旧全局热键继续输出逻辑修饰键和一个动作键；裸 `Esc` 取消，`Backspace` 可录制；
- 映射源保留 `vkCode + scanCode + extended`，支持单键、标准快捷键和一个单级 chord；
- 单独录制一个左/右 Ctrl、Alt、Shift 或 Win 时，该物理修饰键会提升为单键源动作；目标录制不允许只有修饰键；
- chord 由两个同时按住的动作键构成，可另带最多三个修饰键，两个动作键的按下顺序不限；
- 映射目标支持单键或最多四个修饰键加一个动作键，不支持目标 chord；
- 映射模式中的裸 `Esc` 是普通可录制按键，取消由编辑对话框命令完成。

设置窗口和映射对话框不自行安装钩子。开始、结束和迟到结果隔离都由
`KeyboardManager` 的会话号协议处理。

## 3. 钩子顺序

低级钩子回调的处理顺序固定为：

1. 录制捕获；
2. 物理键盘映射；
3. 强制热键和 `Win+字母` 覆盖；
4. Windows 快捷键屏蔽；
5. `CallNextHookEx`。

回调中不等待、不访问文件、不写日志、不获取业务锁，也不动态构建规则。配置在控制
消息处理中先校验并编译为不可变查找表，再整体替换；替换或停止前会释放活动目标键。

## 4. 前缀、回放与注入

引擎只在当前输入是已配置规则前缀时缓冲事件，固定队列最多 16 条。键盘线程使用
`WM_TIMER` 检查 250 ms 截止时间，不在钩子回调中睡眠或等待。

- 完整命中后抑制源序列，并按顺序按下目标修饰键与动作键；
- 源动作键自动重复会重复发送目标动作键 key-down；
- 最后一个源键释放后，目标动作键和修饰键按反序释放；
- 超时、前缀失配或队列溢出时，按原始扫描码、扩展位和 up/down 顺序回放；
- replay 标记使事件跳过映射，但仍可进入现有热键与屏蔽逻辑；
- target 标记使目标输入跳过映射和 Simpilot 热键，防止递归或触发自身动作；
- 其他进程注入的 `LLKHF_INJECTED` 输入不参与映射。

单独物理修饰键源复用 250 ms 定时器，但拥有独立候选标识。首次 key-down 先被暂存；
若截止时间内出现其他键，修饰键 key-down 会先按原始扫描码回放，再继续处理当前键，
因此快速输入 `Ctrl+C` 等组合仍保持原义。修饰键在截止前单独释放时发送一次完整目标
down/up；持续按住至截止时间则按下目标，并在源修饰键释放时按反序释放目标。

单键映射可在无关修饰键已经传递给系统时工作，但运行时会额外保护 `Win+L` 和安全
注意序列：既不吞掉用户原始组合，也不把已按修饰键与目标输出拼成隐式安全组合。

`SendInput` 部分失败时，引擎会尽力释放已发送目标、回放源事件、清空活动状态并设置
诊断标志。钩子回调只发布原子标志，UI 健康检查定时器随后写入日志。

## 5. 进程范围

键盘线程定时读取当前前台进程基名。查询失败时只允许全局规则匹配。作用域选择不依赖
规则编辑顺序，优先级依次为：应用规则高于全局规则、精确匹配高于前缀匹配、更长的
非精确进程前缀高于更短前缀。

“使用当前前台进程”读取键盘线程最近观察到的外部前台进程，避免模态编辑对话框把
Simpilot 自身误填为目标进程。

## 6. 测试与人工边界

自动测试覆盖四类消息、左右修饰键、释放顺序、重复输入、Esc、Backspace、重置、
结果单次消费、单键/快捷键/chord、单独物理修饰键源、严格物理键匹配、250 ms 回放、注入标记、安全
组合旁路、进程优先级、失败恢复和运行时替换释放。

真实桌面仍需人工确认：

- 单键、快捷键和两个动作键同时按住的 chord；
- 左右 Ctrl、Alt、Shift、Win 的物理区分；
- 应用范围、自动重复、不同释放顺序和退出恢复；
- 普通窗口与高权限窗口之间的 UIPI 行为；
- 录制期间系统快捷键不先执行，映射编辑器中裸 `Esc` 可保存。
- 普通右 Ctrl 单独映射到 `左 Win + 左 Shift + F23`，以及快速 `右 Ctrl+C` 的消歧与回放。
