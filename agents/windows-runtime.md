# Windows Runtime Knowledge

## 线程所有权

- UI 线程拥有托盘宿主、菜单、设置及其他窗口，并运行主消息循环；
- 键盘线程拥有消息窗口、`WH_KEYBOARD_LL` 和录制/屏蔽状态；
- 配置监听线程只观察文件并向 UI 投递消息，不直接访问 UI 状态；
- 日志可被不同线程调用，内部使用互斥保护。

跨线程修改必须沿用现有 `PostMessage`、`SendMessageTimeoutW` 或线程停止协议，并明确对象生命周期。

## 关键生命周期约束

- 活动菜单期间会推迟配置重载，防止命令条目指针失效；
- 设置及对话框使用嵌套消息循环，必须正确转交 `WM_QUIT` 并考虑重入；
- Explorer 重启后通过 `TaskbarCreated` 恢复托盘图标；
- 标准热键使用 `RegisterHotKey`，强制接管、录制、物理键映射和 Win+字母屏蔽使用同一个低级钩子；
- 钩子处理顺序固定为录制捕获、映射引擎、强制热键/Win 覆盖、Windows 快捷键屏蔽、`CallNextHookEx`。映射前缀最多缓冲 16 个事件，250 ms 超时由键盘线程定时器处理；钩子回调不得等待、访问文件、写日志或动态分配；
- 映射目标使用独立 `SendInput` 标记，源事件回放使用另一标记；更新或停止映射前先释放活动目标按键。录制结果 mailbox 使用 release/acquire 会话号发布，避免跨线程读取未发布 payload；
- 单键映射遇到已传递的无关修饰键时，不得吞掉或生成隐式 `Win+L`、`Ctrl+Alt+Delete` 等安全组合；
- 键盘线程定时刷新前台进程；查询失败时只允许全局映射匹配。“使用前台应用”读取最近观察到的外部进程，不能直接读取当前模态设置窗口；
- 钩子中的输入失败只发布原子诊断标志，由 UI 健康检查定时器写日志；配置加载的无效映射通过 `AppSettingsStore::DiagnosticSink` 逐条记录；
- Everything SDK 动态加载，缺失或不可用不能阻止 Simpilot 主功能启动。

## 已知风险

- 第二实例当前使用 `HWND_MESSAGE` 范围查找首实例，但托盘宿主是隐藏顶层窗口；
- Everything 服务维护和部分查询会同步占用 UI 线程；
- 键盘健康检查确认线程存活，但检测不到系统静默移除钩子；
- 钩子线程真正挂起时，停止路径可能无限等待；
- 设置保存跨设置文件、菜单文件、图标缓存和运行时状态，依赖补偿式回滚；
- 菜单暗色模式使用未公开的 `uxtheme.dll` 入口，必须保留失败回退；
- 文件夹选择使用旧 Shell API，涉及 COM 初始化的行为尚未完整确认。
- `SendInput` 在不同完整性级别或安全桌面上可能失败；失败时引擎会尽力释放已发送目标并回放源事件，但不能保证跨 UIPI 边界恢复。

这些风险已记录在 `docs/project-state.md`。除非任务明确要求，不要把接管或文档工作扩展成运行时修复。
